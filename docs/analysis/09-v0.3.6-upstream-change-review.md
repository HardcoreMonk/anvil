# ephemera v0.3.6 upstream 변경 검토

## 상태

- 검토일: 2026-05-26
- upstream tag: `v0.3.6`
- peeled commit: `4bd5e8c3d94fbfb862de116caa7417f7b640b325`
- anvil sync branch: `sync/ephemera-v0.3.6`
- 분류: `adapted`

이 문서는 upstream ephemera `v0.3.6`을 anvil runtime baseline으로 받아들일 때의
채택 판단을 기록한다. `v0.3.6`은 control-plane wire format을 바꾸지 않고,
Goosetown flock을 실제 autonomous multi-agent demo까지 확장하는 runtime/demo
릴리즈다.

upstream `main`은 검토 시점에 이미 `v0.4.0` PR-A storage/recovery 변경까지
진행되어 있었다. 이번 sync는 `upstream/main` 전체가 아니라 `v0.3.6` tag commit만
병합한다. `v0.4.0` PR-A는 snapshot/rootfs/recovery 의미가 더 크므로 별도 sync와
adoption review가 필요하다.

## anvil 보안/운영 판단

- `gtcall`은 peer `agent_token`을 VM 내부에 노출하지 않는다. peer 호출은
  control-plane `POST /vms/{vm_id}/tasks` proxy를 통과하며, token injection은 기존
  daemon 경계가 계속 소유한다.
- `gtwall`은 local `/townwall/post`에 VM 자신의 agent token만 사용한다. flock ID와
  agent ID는 `/root/.ephemera-flock` metadata에서 읽고, control-plane token은
  `/root/.ephemera-cp-token` 또는 legacy env fallback을 사용한다.
- `/tasks` response shape는 `{ "output", "error" }`를 유지한다. output 내용은
  Goose JSON envelope에서 assistant text만 추출하는 쪽으로 정리되지만 wire format은
  바뀌지 않는다.
- `curl`과 `jq`가 guest image에 추가된다. host daemon dependency는 늘지 않는다.
  anvil branch는 기존 Trixie minbase와 `libvulkan1` 포함 정책을 유지하고, 여기에
  `curl,jq`만 추가한다.
- `webdev_demo.sh`는 paid-tier Gemini key, `/dev/kvm`, 충분한 memory가 필요한 manual
  demo다. release blocker가 아니라 operator demo 검증 항목으로 취급한다.

## 제외 또는 deferred

- upstream `main`의 `v0.4.0` PR-A storage/recovery 변경은 이번 sync 범위에서 제외한다.
- `webdev_demo.sh`를 IronClaw MCP public tool로 바로 노출하지 않는다. 현재는 runtime
  operator demo이며, IronClaw product workflow로 승격하려면 별도 spec과 MCP tool
  contract가 필요하다.
- peer-to-peer dispatch를 직접 guest-to-guest network API로 노출하지 않는다.
  `gtcall`은 계속 control-plane proxy를 사용한다.

## 검증 기준

최소 검증:

```bash
go test ./...
go build ./cmd/goose-daemon
go build ./cmd/anvil-mcp
go build ./cmd/anvil-scheduler
bash -n webdev_demo.sh
bash -n scripts/build_image.sh
git diff --check
```

KVM host 검증:

```bash
go build -o anvil-daemon ./cmd/goose-daemon/
sudo bash e2e_test.sh
sudo -n bash scripts/vm-workload-e2e.sh
```

`webdev_demo.sh`는 provider key와 paid-tier quota가 있는 운영자가 별도로 실행해
artifact와 secret scan 결과를 release handoff에 기록한다.
