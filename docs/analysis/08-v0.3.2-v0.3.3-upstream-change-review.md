## 기준

- 확인일: 2026-05-19 KST
- upstream: `https://github.com/steve-seungeui/ephemera`
- downstream: `https://github.com/HardcoreMonk/anvil`

## v0.3.2 변경 요약

릴리즈명: `v0.3.2 - Live VM Cold-Restart`

핵심 변화는 daemon 재시작 뒤 이전에 실행 중이던 VM을 같은 identity로 cold-restart하는
기능이다.

주요 내용:

- 모든 성공한 `POST /vms`와 flock member spawn 뒤 `vms/<vm_id>/state.json`을
  원자적으로 기록한다.
- daemon startup에서 `ControlPlane.RecoverVMs`가 저장된 VM state를 읽고 VM을 복구한다.
- 복구 과정은 stale Firecracker process 정리, stale socket/log/vsock artifact 정리,
  기존 TAP/IP/MAC 재예약, 기존 rootfs clone 기반 cold boot, flock association 복원을
  포함한다.
- `cp.vms`를 다시 채워 `/tasks`, `/health`, `/stop`, proxy endpoint가 복구 VM을 즉시
  대상으로 삼을 수 있게 한다.
- graceful daemon shutdown은 Firecracker process와 transient file은 정리하지만
  `state.json`과 rootfs clone은 보존한다.
- 명시적 `DELETE /vms/{id}`는 기존처럼 `state.json`과 rootfs까지 제거한다.

보존되는 것:

- `vm_id`
- `guest_ip`
- `tap_device`
- `mac_addr`
- `agent_token`
- `agent_url`
- profile
- rootfs clone의 disk 내용
- flock membership, Town Wall history, `seq`

보존되지 않는 것:

- in-flight `/tasks`
- VM memory state
- Goose conversation memory
- COW-mode VM과 snapshot-restored VM의 자동 복구

## v0.3.2 anvil 채택 검토 포인트

분류 후보: `deferred` -> sync branch에서 `adapted` 또는 `adopted` 판단 필요.

검토해야 할 점:

- `vms/<vm_id>/state.json`에 `agent_token`이 저장된다. anvil의 불변 조건은
  `POST /vms` 응답 외부로 `agent_token`을 노출하지 않는 것이다. disk persistence는
  runtime 내부 상태로 볼 수 있지만, file mode, log, replay, audit, MCP output으로
  새어나가지 않는지 확인해야 한다.
- graceful daemon shutdown 후 VM이 다음 daemon start에서 되살아나는 의미가 추가된다.
  기존 runbook과 disaster recovery 문서의 "daemon restart 뒤 recovered flock은
  read-mostly" 설명은 v0.3.2 채택 시 바뀐다.
- COW-mode와 snapshot-restored VM은 자동 복구 범위 밖이다. anvil snapshot/restore
  문서와 혼동되지 않게 제한을 명시해야 한다.
- full KVM E2E는 `57e`, `57f` cold-restart 검증을 포함하는 upstream 버전으로
  갱신해야 한다.

## v0.3.3 변경 요약

릴리즈명: `v0.3.3 - Operational Polish`

핵심 변화는 v0.3.2의 cold-restart 기반 위에서 운영 rough edge를 줄이는 것이다.

주요 내용:

- Watchdog이 agent status를 `dead`로 바꾸면 `flocks/<id>/metadata.json`에 즉시
  persist한다.
- `Flock.Persist(workDir)`와 per-flock `writeMu`가 추가되어 createFlock, watchdog,
  recovery, per-agent restart가 동시에 metadata를 쓸 때 파일을 찢지 않게 한다.
- 단일 agent 재시작 endpoint가 추가된다:
  `POST /flocks/{flock_id}/agents/{agent_id}/restart`
- per-agent restart는 해당 flock member VM만 제거하고 다시 spawn한다. `agent_id`,
  role, 기존 `agent_token`은 유지하고, 새 `vm_id`와 `agent_url`을 부여한다.
- auth-on control plane에서 in-VM `/townwall/post`가 동작하도록 host control-plane
  token을 flock VM 내부 `/root/.ephemera-cp-token`에 `0600` mode로 자동 주입한다.
- `cmd/goose-agent`는 `/root/.ephemera-cp-token`을 우선 읽고, legacy
  `EPHEMERA_CONTROL_PLANE_TOKEN` 환경 변수로 fallback한다.
- `e2e_test.sh`에 real-LLM Town Wall round-trip smoke가 추가됐다. provider key가
  없으면 skip하고, 있으면 `/tasks -> Goose CLI -> gtwall -> in-VM forwarder -> CP
  Town Wall` chain을 검증한다.

## v0.3.3 anvil 채택 검토 포인트

분류 후보: `deferred` -> sync branch에서 `adapted` 또는 `adopted` 판단 필요.

검토해야 할 점:

- `POST /flocks/{flock_id}/agents/{agent_id}/restart`는 anvil MCP tool surface로
  바로 노출할지, daemon-only 운영 기능으로 둘지 결정해야 한다.
- per-agent restart는 기존 `agent_token`을 재사용한다. response에 token을 새로
  노출하지 않는지, MCP output에 포함하지 않는지 확인해야 한다.
- `/root/.ephemera-cp-token`은 host control-plane token을 guest disk에 넣는다.
  이는 auth-on Town Wall forwarding을 자동화하지만, guest compromise 시 CP token
  노출 blast radius가 커진다. token rotation, least-privilege token, file mode,
  profile별 정책을 함께 검토해야 한다.
- upstream release note는 CP token rotation이 수동이라고 명시한다. SIGHUP token
  rotation 뒤에는 affected VM을 restart하거나 flock을 재생성해야 한다.
- real-LLM e2e는 실제 provider key를 환경 변수로 사용한다. `GOOGLE_API_KEY`,
  `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` 값은 문서, commit, replay fixture에 남기면
  안 된다.


runtime lifecycle, token persistence, in-VM CP token 주입이 포함되므로 KVM host에서는
다음 검증도 필요하다.

```bash

sudo bash e2e_test.sh
scripts/anvil-mcp-e2e.sh flock
```

실제 LLM smoke를 실행할 때는 provider key를 환경 변수로만 넘기고, 실행 후 replay
fixture와 git diff에 key가 남지 않았는지 별도 확인한다.
