# ephemera v0.4.0-v0.4.5 runtime 안정화 변경 분류

## 상태

- 검토일: 2026-06-09
- upstream 범위: `v0.3.6..v0.4.5`
- 기준 baseline: anvil `main`의 upstream ephemera `v0.3.6` 병합분
- upstream 최신 검토 대상:
  - `v0.4.0`: `ae8ebc59622f358c9784fb70578f999fd058bd2a`
  - `v0.4.1`: `f8944d97dc0fc864afe6772ce8111f20a2289d8f`
  - `v0.4.2`: `dc97245e060e63d8c102ad446dcf1ef203d2d667`
  - `v0.4.3`: `eb3f3a31a24986af57caa71183c99571217e7bd1`
  - `v0.4.4`: `7de4083771e04f74d370317a88f19abac29cebb8`
  - `v0.4.5`: `c1421de3dafc0727772f9058552d993575386da6`
- diff 규모: 45 files changed, 6595 insertions, 531 deletions
- 분류 상태: pre-sync adoption review. 아직 anvil runtime baseline으로 병합하지 않았다.

이 문서는 upstream ephemera `v0.4.0`부터 `v0.4.5`까지의 runtime 안정화 변경을
anvil 보안/운영 정책에 맞춰 `adopted`, `adapted`, `deferred`, `excluded`로
예비 분류한다. 실제 반영은 `sync/ephemera-v0.4.x` 계열 merge commit branch에서
충돌 해결, full KVM 검증, 문서 갱신을 거쳐 확정한다.

## 요약 판단

| upstream | 주제 | anvil 예비 분류 | 이유 |
|---|---|---|---|
| `v0.4.0` | storage/recovery core | `adapted` | cleanup, snapshot dependency, COW recovery는 필요하지만 auto-snapshot과 rootfs diff는 anvil snapshot replication/GC와 함께 조정해야 한다. |
| `v0.4.1` | auth/audit/operator interfaces | `adapted` | client identity, access audit, token TTL은 채택 가치가 높다. `ephemera-ctl`은 runtime operator tool로 유지하고 anvil MCP public surface로 승격하지 않는다. |
| `v0.4.2` | COW spawn default | `adapted` + default flip `deferred` | COW spawn probe/fallback은 채택하되 anvil 기본값을 즉시 `cow`로 바꾸는 것은 KVM burn-in 뒤 결정한다. |
| `v0.4.3` | flock lifecycle | `adapted` | single-host flock 동적 관리와 Town Wall 보강은 유용하지만 routed members-only cross-host flock에는 그대로 적용하지 않는다. |
| `v0.4.4` | streaming/tasks/watchdog/broadcast | `adapted` | streaming과 depth guard는 중요하다. broadcast는 rate/tenant/audit 경계가 있어 MCP 노출은 별도 설계가 필요하다. |
| `v0.4.5` | snapshot-restored VM recovery | `adapted` | limitation을 줄이지만 snapshot GC와 source snapshot dependency 보호를 anvil 정책에 맞춰 강화해야 한다. |

제외(`excluded`) 대상은 현재 없다. 다만 몇몇 public exposure는 `deferred`다.

## 세부 분류

### v0.4.0 Storage / Recovery Core

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| COW spawn cold-restart | `adapted` | `vms/<vm_id>/state.json`에 anvil의 `tenant_id`, `egress_policy`, profile, routed placement와 충돌하는 필드가 보존되는지 확인한다. graceful shutdown은 state/rootfs를 보존하되 explicit delete는 TAP/IP, dm-snapshot, loop, bind mount, COW store를 정리해야 한다. |
| true rootfs diff snapshots | `adapted` | `rootfs_diff_path` metadata를 snapshot export/import, `anvil_replicate_snapshot`, dependency guard에 반영한다. diff snapshot은 base full snapshot 삭제를 계속 막아야 한다. |
| disk-space pre-flight | `adopted` | clone/snapshot/restore/export/import/replication 경로에서 `507 Insufficient Storage` 의미를 유지한다. MCP는 sanitized error만 전달하고 daemon raw body를 audit에 저장하지 않는다. |
| orphan COW inventory/reclaim | `adapted` | crash 이후 orphan dm/loop cleanup은 채택한다. cleanup 대상 판별은 anvil runtime artifact만 다루고 local secret/profile 파일을 건드리지 않아야 한다. |
| memory auto-snapshot (`EPHEMERA_AUTOSNAPSHOT=true`) | `deferred` public support, code path는 `adapted` | 기본값은 계속 off로 둔다. full memory image disk cost, graceful-only 의미, in-flight task 손실/복구 정책을 운영 문서에 명시한 뒤 opt-in으로만 지원한다. |
| spawn/recovery rollback | `adopted` | TAP/IP, disk clone, dm device leak 방지에 직접 필요하다. anvil invariant "VM 삭제 실패 경로에서도 host resource cleanup"과 일치한다. |
| Firecracker signal forwarding fix | `adopted` | SIGHUP/SIGTERM race를 줄이는 안전 변경이다. token reload와 graceful shutdown 검증에 포함한다. |

### v0.4.1 Operational Interfaces

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| client identity in request context | `adapted` | daemon auth client identity를 audit/metrics에 쓰되 `ANVIL_API_TOKEN`의 프로세스별 의미 혼동을 문서에 유지한다. |
| access audit log + `GET /audit` | `adapted` | Authorization header, token, request/response body, query string 미저장 원칙을 유지한다. anvil MCP audit JSONL과 중복되므로 "daemon access audit"과 "MCP tool audit"을 분리해서 문서화한다. |
| per-token TTL/rotation | `adapted` | `EPHEMERA_API_TOKENS`/`ANVIL_API_TOKENS` alias precedence와 함께 검증한다. in-VM CP token은 first non-expired client만 주입해야 한다. |
| `ephemera-ctl` operator CLI | `deferred` for anvil public surface | runtime operator tool로 빌드는 허용할 수 있지만 IronClaw/anvil MCP 계약으로 승격하지 않는다. 이름도 `ephemera-ctl`을 유지한다. |

### v0.4.2 COW Spawn by Default

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| `storage.DMSnapshotAvailable()` probe/fallback | `adopted` | host dm-snapshot 가용성을 startup에서 확인하고 plain fallback을 명확히 log/metrics로 남긴다. |
| COW spawn support for diff snapshots | `adapted` | COW + Diff snapshot 조합을 anvil snapshot replication과 함께 검증한다. |
| default `EPHEMERA_DISK_MODE=cow` | `deferred` | anvil 운영 기본값은 당장 바꾸지 않는다. full KVM e2e, cleanup stress, snapshot GC/replication 검증 뒤 default flip을 별도 결정한다. |

### v0.4.3 Flock Lifecycle

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| dynamic add/remove/role-change | `adapted` | single-host daemon flock에는 채택 가능하다. routed members-only cross-host flock에는 적용하지 않고 unsupported 또는 별도 cross-host 설계로 둔다. |
| pause/resume | `adapted` | watchdog이 paused VM을 dead로 오판하지 않는 점은 채택한다. pause state가 runtime-only인 점은 운영 문서에 명시한다. |
| per-flock `max_agents` | `adapted` | daemon cap과 anvil scheduler/tenant quota가 충돌하지 않도록 더 작은 제한을 적용하는 정책이 필요하다. |
| Town Wall history filters | `adopted` | read-only inspection 기능이며 MCP `anvil_get_townwall_history` 확장 후보가 된다. |
| Town Wall log rotation | `adapted` | rotated backups retention을 daemon audit retention과 같은 운영 문서에서 설명한다. history API가 active log만 보는 제한을 명확히 한다. |

### v0.4.4 Feature Extensions

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| flock broadcast | `deferred` for MCP public surface, daemon path는 `adapted` | 모든 agent에 prompt를 분산 실행하므로 tenant quota, rate limit, audit, cancellation 정책이 필요하다. single-host daemon endpoint는 채택 가능하지만 `anvil_*` MCP tool 노출은 별도 spec 이후다. |
| `GET /watchdog/status` | `adopted` | read-only operational endpoint다. auth 보호와 audit 기록을 유지한다. |
| streaming `/tasks?stream=1` | `adapted` | buffered `/tasks` wire behavior는 유지한다. MCP stdio surface는 streaming frame을 그대로 노출하지 않고 별도 tool/transport 검토가 필요하다. |
| nested invocation depth guard | `adopted` | `gtcall` loop 방지에 필요하다. `EPHEMERA_MAX_TASK_DEPTH` 기본값과 508 response를 문서화한다. |
| `goose-agent` slog migration | `adapted` | golden image rebuild가 필요하다. host/guest log format env 동작과 default level을 KVM smoke에서 확인한다. |

### v0.4.5 Snapshot-Restore Auto-Recovery

| 기능 | 분류 | anvil 적용 조건 |
|---|---|---|
| restored VM `state.json.source_snapshot_id` | `adapted` | restored VM recovery는 채택 가치가 높다. 다만 snapshot GC는 live restored VM이 참조하는 source snapshot을 삭제하면 안 된다. |
| `recoverRestoredVM` re-restore | `adapted` | 복구 의미는 "마지막 restore 이후 write 보존"이 아니라 "source snapshot 시점으로 재복구"다. MCP/README에 명확히 써야 한다. |
| bind-mount fallback restored VM recovery 제외 | `adopted` as limitation | dm-snapshot tooling이 없는 host에서는 limitation을 유지한다. |
| source snapshot deleted while restored VM runs | `adapted` | recovery drop/failed surfacing은 채택하되, anvil snapshot retention/GC는 source snapshot 삭제를 사전에 막는 쪽으로 강화한다. |

## anvil 충돌 예상 지점

- `cmd/goose-daemon/api.go`, `orchestrator_api.go`, `recovery.go`는 anvil의
  tenant/egress, scheduler-aware routing, token redaction 변경과 충돌 가능성이 높다.
- `internal/storage/snapshot.go`, `vm_state.go`, `orphan.go`는 anvil snapshot
  export/import, cross-host replication, retention GC와 함께 재검토해야 한다.
- `cmd/goose-agent/main.go`와 `scripts/gtcall` 변경은 golden image rebuild를 유발한다.
  KVM smoke 없이 release하지 않는다.
- `ephemera-ctl`은 upstream runtime operator CLI다. anvil product rename 대상이 아니며,
  IronClaw MCP adapter의 대체물로 설명하지 않는다.
- `POST /vms` 외부의 `agent_token` 노출 금지는 계속 적용한다. upstream flock add-agent
  응답이 one-time `agent_token`을 반환하는 경로는 anvil public/MCP surface로 그대로
  노출하지 않는다.

## 권장 sync 순서

1. `sync/ephemera-v0.4.0-runtime-core`에서 storage/recovery core를 먼저 병합한다.
   `auto-snapshot`은 opt-in/off 상태로 두고, rootfs diff snapshot metadata와
   anvil snapshot replication manifest를 맞춘다.
2. `v0.4.1` auth/audit/token TTL을 병합한다. daemon access audit과 MCP tool audit의
   책임 경계를 문서화한다.
3. `v0.4.2` COW probe/fallback과 COW+Diff support를 병합하되, default `cow` 전환은
   별도 KVM burn-in 뒤 결정한다.
4. `v0.4.3` single-host flock lifecycle을 병합한다. routed members-only flock에는
   unsupported contract를 유지한다.
5. `v0.4.4` streaming/depth guard/watchdog status를 병합한다. broadcast MCP exposure는
   deferred로 남긴다.
6. `v0.4.5` restored VM recovery를 병합하고 snapshot GC dependency guard를 확장한다.

## 검증 기준

CI-safe 최소 검증:

```bash
go test ./...
go build ./cmd/goose-daemon
go build ./cmd/anvil-mcp
go build ./cmd/anvil-scheduler
go build ./cmd/ephemera-ctl
git diff --check
```

KVM host 검증:

```bash
go build -o anvil-daemon ./cmd/goose-daemon/
sudo bash e2e_test.sh
scripts/anvil-mcp-e2e.sh lifecycle
scripts/anvil-mcp-e2e.sh flock
scripts/vm-workload-e2e.sh
```

추가 anvil 전용 확인:

- MCP output, audit, metrics, docs에 `agent_token`/Authorization header/daemon raw body가
  새로 노출되지 않는지 확인한다.
- routed members-only flock registry가 single-host flock lifecycle 변경에 의해
  resurrect되지 않는지 확인한다.
- `anvil_replicate_snapshot`이 `rootfs_diff_path`와 restored VM `source_snapshot_id`
  dependency를 이해하는지 확인한다.
- full snapshot을 참조하는 diff snapshot, live restored VM이 참조하는 source snapshot은
  삭제되지 않아야 한다.
