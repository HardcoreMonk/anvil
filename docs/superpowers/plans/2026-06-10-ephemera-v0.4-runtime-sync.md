# Ephemera v0.4 Runtime Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring ephemera `v0.4.0`-`v0.4.5` runtime stabilization into anvil while preserving anvil's IronClaw MCP boundary, token redaction rules, tenant/egress metadata, scheduler state, and cross-host snapshot/flock work.

**Architecture:** Use merge commits from upstream tags in chronological order, not cherry-picks or rebases. After each tag merge, re-apply anvil policy at the daemon/storage/MCP boundary: `agent_token` appears only in `POST /vms`, daemon raw bodies stay out of MCP audit/output, `EPHEMERA_*` compatibility names and `ANVIL_*` aliases both remain valid, and routed members-only flock state stays separate from daemon `FlockManager` state. Keep risky upstream defaults opt-in until KVM burn-in proves them.

**Tech Stack:** Go standard library, Firecracker Go SDK, existing ephemera daemon/storage/network/orchestrator packages, existing `internal/anvilmcp` router/store/MCP tooling, upstream git tags, markdown docs.

---

## File Structure

- Modify `cmd/goose-daemon/config.go`: add `maxTaskDepth`, `diskMinFreeMiB`, `enableAutoSnapshot`, token expiry parsing, first-active-client selection, and disk-mode resolver while preserving `ANVIL_*` aliases and keeping anvil's default disk mode as `plain`.
- Modify `cmd/goose-daemon/api.go`: merge spawn rollback, disk-space preflight, audit middleware, depth forwarding, streaming task proxy, COW/recovery fields, snapshot-restored VM state, and flock lifecycle routes while preserving tenant/egress fields and token redaction.
- Create `cmd/goose-daemon/audit.go` and `cmd/goose-daemon/context.go`: daemon access audit and authenticated client context helpers from upstream, adapted to never log query strings, bodies, headers, or tokens.
- Modify `cmd/goose-daemon/orchestrator_api.go`: add single-host flock add/remove/role-change, pause/resume, broadcast, watchdog status route, and Town Wall filters; redact upstream add-agent token responses for anvil.
- Modify `cmd/goose-daemon/recovery.go`: add COW recovery, auto-snapshot fallback, artifact-missing cleanup, restored-VM re-restore, and source snapshot failure surfacing.
- Modify `cmd/goose-agent/main.go` and `scripts/gtcall`: merge streaming/depth/slog support; this triggers golden image rebuild and therefore requires KVM smoke.
- Create `cmd/ephemera-ctl/*`: keep upstream operator CLI as `ephemera-ctl`; do not rename it and do not present it as an anvil MCP replacement.
- Modify `internal/storage/diskspace.go`, `internal/storage/orphan.go`, `internal/storage/snapshot.go`, `internal/storage/vm_state.go`: add disk preflight, rootfs diff snapshots, COW orphan reclaim, auto-snapshot helpers, and `source_snapshot_id` recovery state; preserve anvil snapshot bundle/export/import scrubbing.
- Modify `internal/network/manager.go` and `internal/vm/machine.go`: merge idempotent release, COW device reclaim support, vsock command helpers, signal forwarding restrictions, and depth/stream-safe runtime behavior.
- Modify `internal/orchestrator/flock.go`, `internal/orchestrator/townwall.go`, `internal/orchestrator/watchdog.go`: merge lifecycle fields, max agent cap, pause state, log rotation, history filters, and watchdog status.
- Modify `internal/anvilmcp/*`: update daemon client structs only where daemon wire formats changed; do not expose flock broadcast or streaming MCP tools in this phase.
- Modify `README.md`, `RELEASE_NOTES.md`, `CONTEXT.md`, `docs/ADR_INDEX.md`, `docs/PUBLIC_RELEASE_BOUNDARY.md`, `docs/architecture/*.md`, and `docs/operations/*.md`: document adopted/adapted/deferred decisions and runbook changes.

- Keep `HardcoreMonk/anvil` as a fork; use merge commits on `sync/ephemera-v0.4-runtime-core`.
- Do not fetch tags with `--force`.
- Do not expose `agent_token` outside `POST /vms`.
- Do not let upstream `EPHEMERA_DISK_MODE=cow` default flip anvil's default in this phase.
- Do not publish flock broadcast as an `anvil_*` MCP tool in this phase.
- Do not remove existing anvil snapshot bundle, scheduler, tenant/egress, runtime audit, or routed flock tests.

	cp := &ControlPlane{

			"vm-restored": {
				VMInfo: VMInfo{VMID: "vm-restored"},
