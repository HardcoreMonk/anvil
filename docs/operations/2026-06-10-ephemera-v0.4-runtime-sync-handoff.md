## Phase 1 KVM gate 중 고친 pre-existing latent defect

두 결함 모두 이번 sync가 만든 것이 아니라 gate에서 드러난 기존 결함이다.

- `4c1c803`: restore handler가 COW device를 per-restore path 위에 bind-mount하는
  동안 Firecracker `LoadSnapshot`은 `state.bin`(`meta.DiskPath`)에 기록된 path를
  연다. source VM 삭제 후의 모든 restore가 v0.4.0 적응 이후 `500`으로 실패하던 문제를
  `meta.DiskPath` 위로 restore하도록 고쳐 upstream 및 recovery 경로와 일치시켰다.
  결함을 고정하던 v0.4.0-era test assertion 두 개도 함께 수정했다.
- `38fbedc`: anvil 전용 `EnsureGoldenImageGooseAgent`가 시작 시 golden image를
  무조건 loop-mount해 SIGKILL crash 후 COW VM이 image를 pin한 상태에서 `EBUSY`로
  죽던 문제를, agent-stamp(source hash + image size + mtimeNs)가 current면 mount를
  건너뛰도록 고쳤다. live COW VM이 origin을 pin한 채 agent hash가 바뀌는 경우의
  loud-fail은 의도적으로 유지한다.

## 의도적 divergence (upstream 대비, `adapted`)

upstream e2e 46c는 live restored VM이 참조하는 source snapshot의 `DELETE`를 `200`으로
허용하고 restored VM을 orphan으로 둔다. anvil은 이 `DELETE`를 `409`로 막고 restored
VM을 먼저 삭제한 뒤 snapshot을 삭제하도록 요구한다. `e2e_test.sh`의 46c 단계는 이
divergence에 맞게 조정했고(commit `63df804`, divergence 주석 포함) 같은 divergence를
[`docs/ADR_INDEX.md`](../ADR_INDEX.md)와
[`docs/operations/upstream-sync-policy.md`](upstream-sync-policy.md)에 `adapted`로
기록한다.
