### 경계

- operator Web UI(`/ui/`)와 `/config/*` surface는 **runtime/operator surface이고
  IronClaw MCP surface가 아니다**. `cmd/anvil-mcp`는 v0.5 sync에서 변경되지 않았고,
  daemon `VMInfo`의 additive `provider`/`model` 필드만 daemon/UI가 소비한다.
- auth 밖에 두는 surface는 `/ui/`(정적 bundle + login)뿐이다. `/config/profiles`·
  `/config/providers`·`/config/clients`를 포함한 모든 data API는 auth 설정 시 bearer
  뒤에 유지한다(guard `config_api_anvil_test.go`).
- `/config/*` surface는 `goose-secrets.yaml` 값(API key)이나 control-plane token
  값을 응답에 담지 않는다(sentinel test).

## Sizing 결정 (KVM 근거로 승인)

`v0.5.3`부터 anvil은 upstream default VM sizing `1` vCPU / `1024` MiB를 채택한다
(v0.5.3 이전 2/2048). full e2e 3× `316✓`가 1024에서 통과했다. snapshot metadata가
per-VM sizing을 기록하고 legacy snapshot(0)은 restore 시 2/2048로 fallback한다.

**Known upstream-inherited gap (follow-up):** flock member spawn이 per-profile
`EPHEMERA_VCPU_COUNT`/`EPHEMERA_MEM_SIZE_MIB` override를 무시하고 `LookupProfile`
default로만 sizing한다(`POST /vms`는 override를 존중). flock member는 아직 default
sizing만 받는다.

## Phase 2 KVM gate 중 고친 latent defect (`64ec57c`)

분류: `v0.5.x` `gracefulAgentStop`이 v0.2.0부터 잠재하던 upstream shared pooled-client
결함을 드러냈다(이번 sync가 만든 결함 아님). control plane은 모든 `/vms/{id}/*`를 하나의
long-lived keep-alive `agentHTTPClient`로 proxy하는데, guest IP가 VM
destroy/create/restore 사이에 재활용된다. destroy된 VM으로 향하던 stale pooled
connection이 idle pool에 half-open으로 남고(guest는 delayed shutdown 전에
force-stop됨 — `v0.5.x` `gracefulAgentStop`이 window를 넓힘), snapshot-restored VM이
같은 IP를 재사용하면 다음 proxied `POST /tasks`가 stale connection을 재사용한다.
proxied body는 rewindable하지 않아 net/http가 재시도할 수 없고, `502`(peer RST) 또는
unbounded hang(black-holed packet)으로 caller에게 표면화됐다(Phase 2 gate step 15
"Run task on restored VM"). fix는 proxy client의 keep-alive pooling을
끄고(`DisableKeepAlives`) request마다 fresh dial하며 connection-reuse guard test를
추가한다. upstream connection pooling과의 의도적 divergence이며 upstream 기여 후보다.

## 운영 주의 — KVM gate 전제

KVM gate 스크립트는 working directory에 gitignore된 로컬 operator 파일
`configs/goose.yaml`과 `configs/goose-secrets.yaml`이 있어야 한다. 없으면 `POST /vms`가
config injection 단계에서 `500`으로 실패한다. `anvil-mcp-e2e.sh semantic`과
real-LLM smoke는 추가로 유효한 provider API key가 필요하다. 이 파일들은 release
artifact에 포함하지 않는다.
